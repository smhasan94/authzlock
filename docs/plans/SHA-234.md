Implementation plan

Ticket: SHA-234 Action end-to-end test on the fixture scenario. Written 2026-09-30. Assumes
the AC3 wording amendment proposed alongside this plan is approved (the dispatch job takes a
PR number input instead of a permanently designated test PR). Builds on SHA-232 and SHA-231.

## Approach

A second workflow, `.github/workflows/action-e2e.yml`, separate from `ci.yml` so the SHA-184
guards stay untouched. Job `loosened`: check out, copy `scenario_loosen` into a temp
directory, `git init`, commit the fixture and lockfile, apply the loosening edit, then run
the local action with `uses: ./`, `fail-on-loosened: false`, `comment: false` and a
`working-directory` pointing at the temp repo; the action writes its markdown to
`authzlock-diff.md`, and `scripts/ci/assert_summary.py` asserts the summary counts are
exactly `1 loosened, 0 tightened, 0 added, 0 removed, 0 changed-unknown` and that the row
contains `DELETE` and the view name. Job `clean`: same without the edit, expecting "no
access-control changes". Job `fails-when-loosened`: runs the action with the default
`fail-on-loosened` under `continue-on-error: true` and asserts `steps.run.outcome ==
'failure'`. A `workflow_dispatch` job `sticky-comment` takes `pr_number` and runs the action
with `comment: true` against that PR twice, then asserts through `gh api` that exactly one
marker comment exists.

Rejected: testing on the repo's own PR (the repo is not a Django project); a nested
checkout of another repo (needs a token and a second repo).

## Changes

- `.github/workflows/action-e2e.yml`, `scripts/ci/assert_summary.py`.
- `tests/test_assert_summary.py`; `docs/github-action.md` "testing" section.

## Test mapping

- T1 -> the `loosened` job on this PR; run URL recorded.
- T2 -> the `clean` job; run URL recorded.
- T3 -> `sticky-comment` dispatch against a PR opened for the purpose and closed after;
  run URLs and the final comment count recorded.
- T4 -> `tests/test_assert_summary.py::test_t4_summary_parser_accepts_expected_and_rejects_other`.
- T5 -> the `fails-when-loosened` job; run URL recorded.

## Sequence

1. `assert_summary.py` and T4.
2. Workflow with the three automatic jobs; iterate until green on the PR.
3. Dispatch the sticky-comment job twice against a throwaway PR; record; close it.

## Risks and unknowns

- `uses: ./` requires the action to be in the checked-out tree, which it is on PRs from
  this repo; fork PRs are out of scope.
- The action's `pip install` of the checkout must succeed on the runner's default Python.

## Out of scope

Marketplace listing; other repos. No follow-up tickets needed.
