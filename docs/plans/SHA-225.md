## Approach

`cli.py` gains the `update` command and the option conventions every command reuses:
`--settings` (overrides `DJANGO_SETTINGS_MODULE`), `--lockfile` (default `authz.lock`
relative to the current directory) and `--quiet`. A helper `_extract_or_exit(settings)`
calls `load_project` and `extract()` and turns any `AuthzlockError` into one or two stderr
lines plus exit code 2, with the "what to do" hint carried by the error itself. `update`
dumps the inventory, compares the text with the existing file and writes only on change,
printing "authz.lock: 12 routes written" or "authz.lock: unchanged". Exit codes live in
`errors.py` as `EXIT_OK`, `EXIT_DIFF`, `EXIT_ERROR`. `src/authzlock/__main__.py` makes
`python -m authzlock` equivalent to the console script. Because extraction sets up Django
in-process, CLI integration tests run the CLI as a subprocess through a harness helper
`run_cli(args, fixture, cwd)`; in-process `CliRunner` is used only for argument errors that
never reach Django.

Rejected: a global config object for options (over-engineering for three options); running
Django setup inside the pytest process (breaks fixture isolation).
