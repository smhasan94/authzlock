## Approach

The supported matrix is one module-level constant in `noxfile.py`, `SUPPORTED`, a list of
`(python, django)` pairs: Django 4.2 on 3.10 to 3.12 and Django 5.1 and 5.2 on 3.10 to 3.13,
eleven cells. The `tests` session is declared with `@nox.parametrize("python,django",
SUPPORTED)` so `nox -l` lists exactly those cells and never an unsupported pair; nothing is
skipped at runtime. Each session installs `-e .[dev]`, then overrides `django~=X.Y.0` and
`djangorestframework>=3.16` (the first DRF release supporting Django 5.2), exports
`AUTHZLOCK_DJANGO=X.Y` and runs `pytest`. Tests import `SUPPORTED` from the noxfile, so
SHA-184's CI matrix test can reuse it. nox uses the uv backend when present for speed.

Rejected: a `session.skip()` guard for Django 4.2 on 3.13 (would still appear in `nox -l`,
failing AC2); tox (nox is the convention); Django 5.0 as a cell (end of life April 2025).

## Changes

- `pyproject.toml`: `[tool.pytest.ini_options]` gains `addopts = "-ra --strict-markers"`,
  `markers = ["slow: ..."]`, `xfail_strict = true`.
- `noxfile.py`: `SUPPORTED`, `PYTHONS`, `DJANGOS` constants; `tests` session; `nox.options`
  sessions extended with `tests`; `default_venv_backend = "uv|virtualenv"`.
- `tests/conftest.py`: `repo_root` fixture; `run_python(args, env)` subprocess helper.
- `tests/test_smoke.py`, `tests/test_nox_matrix.py`, `tests/test_pytest_config.py`,
  `tests/test_fixtures_readme.py`.
- `tests/fixtures/README.md`: naming rule (`<style>/` with a `settings.py`, one per view
  style) and how `run_extract` selects one (defined in SHA-197).

## Test mapping

- T1 -> `tests/test_smoke.py::test_version_is_nonempty_string`.
- T2 -> `tests/test_nox_matrix.py::test_session_list_matches_supported_matrix` (loads the
  noxfile with `importlib`, compares the parametrized session names with the eleven expected).
- T3 -> `tests/test_smoke.py::test_django_version_matches_session` (reads
  `AUTHZLOCK_DJANGO`; skipped when unset so plain `pytest` still passes).
- T4 -> `tests/test_pytest_config.py::test_failing_test_fails_run` (subprocess pytest on a
  temp file with `assert False`; expects exit code 1).
- T5 -> `tests/test_fixtures_readme.py::test_fixture_readme_present`.
- T6 -> `tests/test_nox_matrix.py::test_no_unsupported_pairs` (no cell pairs Django 4.2 with
  Python 3.13; every cell uses a Python from `PYTHONS`).
- T7 (from SHA-182) -> `tests/test_nox_matrix.py::test_claude_md_commands_name_real_sessions`.
- Extra: `tests/test_nox_matrix.py::test_supported_covers_every_django_and_python` (each
  Django version and each Python appears at least once).

## Sequence

1. pytest config, `conftest.py`, smoke test. `pytest` green.
2. `SUPPORTED` and the `tests` session. `nox -l` shows eleven cells; run one cell.
3. `AUTHZLOCK_DJANGO` plumbing and T3; run a 4.2 and a 5.2 cell.
4. Fixtures README and T5.
5. Matrix tests T2, T6, T7 and the extra. `pytest` green.
6. `uv python install 3.10`, then `nox -s tests` across all cells once with
   `--reuse-existing-virtualenvs`.

## Risks and unknowns

- Python 3.10 is not installed locally. `uv python install 3.10` fixes it in minutes.
- Parametrizing `python` through `nox.parametrize` is supported but less common. Step 2's
  `nox -l` check comes before anything depends on it.
- Eleven cells are slow locally. Reused virtualenvs and the uv backend keep a full run
  under about ten minutes; CI parallelises them in SHA-184.
- DRF 3.16 is required for Django 5.2, so the matrix never exercises DRF 3.14 or 3.15. The
  brief claims 3.14+ compatibility. Follow-up ticket filed (see below).

## Out of scope

CI workflow (SHA-184); fixture Django projects and `run_extract` (SHA-197); coverage
thresholds. Follow-up filed: "Matrix cell for minimum DRF 3.14 on Django 4.2", blocked by
SHA-183, so the 3.14+ claim gets a test.
