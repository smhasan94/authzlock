Implementation plan

Ticket: SHA-200 URL resolver walk and route model. Written 2026-09-30. Builds on SHA-197.

## Approach

`model.Route` becomes a frozen, keyword-only dataclass with `path`, `name`, `view` and the
later fields defaulted (`methods=()`, `actions={}`, class lists and sources `None`,
`django_auth=None`, `object_scoping=None`). `extract/urls.py::walk_urlconf()` starts from
`django.urls.get_resolver()` and recurses: for a `URLResolver` it appends `str(pattern)` to
the prefix and pushes `namespace` when set; for a `URLPattern` it emits a `RawRoute(path,
name, callback)`. Names are joined with `:` through the namespace stack; `app_name` without
an explicit namespace counts as the namespace, as Django does. `i18n_patterns` resolvers are
walked like any other. View identity: `callback.view_class` when present (class-based
`as_view()`), else the callback itself; the dotted path is `module + "." + qualname` after
following `__wrapped__` while the object has one, which handles `functools.wraps` and, for
a wrapper without it, records the wrapper's own name (no crash). `extract()` maps raw
routes to `Route` and sorts by `(path, view)`.

Rejected: `django.urls` reverse-based enumeration (misses unnamed routes); the
`show_urls` approach from django-extensions (extra dependency, same walk).

## Risks and unknowns

- `str(pattern)` differs between `RoutePattern` (`shop/<int:pk>/`) and `RegexPattern`
  (`^shop/(?P<pk>\d+)/$`); the lockfile keeps each as Django reports it, and T5 pins the
  regex form. Prefix joining must not strip the `^` of a nested regex; test with a nested
  `re_path` include.
- Admin routes, if a fixture adds `django.contrib.admin`, produce many entries; fixtures
  do not include admin.
