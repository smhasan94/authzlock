Implementation plan

Ticket: SHA-211 Custom permission class registry. Written 2026-09-30. Builds on SHA-205.

## Approach

`extract/custom.py` owns two things. `render_permission(obj) -> str` turns a permission
class or DRF operand holder into a stable string: a class becomes its dotted path;
`OperandHolder` becomes `(<left> <op> <right>)` with `|` for `OR` and `&` for `AND`;
`SingleOperandHolder` becomes `(~<operand>)`. Nothing is instantiated. `Registry.collect()`
walks every route's rendered permission classes, extracts each dotted path whose module is
not `rest_framework.permissions`, and records `name`, the first paragraph of
`inspect.getdoc` or `null`, and the sorted `used_by` route keys. SHA-205's placeholder
renderer is replaced by this one.

Rejected: treating third-party permission classes as built-in (unknown semantics; custom is
the conservative label); importing classes by string (they are already objects).
