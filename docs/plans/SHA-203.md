## Approach

`extract/methods.py::methods_for(callback) -> tuple[list[str], dict[str, str]]` with three
branches. ViewSet callables from routers carry `callback.actions` (`{"get": "list", ...}`):
methods are its keys upper-cased and sorted, `actions` maps upper method to action name.
Class-based views: `view_class.http_method_names` intersected with the handler names the
class actually implements (`hasattr(view_class, m)`), minus `head` and `options`. Function
views: walk the `__wrapped__` chain and inspect closures with `inspect.getclosurevars`; the
`require_http_methods` family stores `request_method_list` in the closure, which gives the
exact list (`require_safe` yields GET). No decorator found means `["any"]`. Methods are
always upper-case, sorted, and never include HEAD or OPTIONS.

Rejected: calling `view.options()` or sending fake requests (executes project code);
treating function views as accepting all seven methods (misleading; `any` is honest).
