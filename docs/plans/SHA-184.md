Implementation plan

Ticket: SHA-184 CI workflow on pull requests. Written 2026-09-30. Assumes the T2, T3 and T5
amendments proposed alongside this plan are approved. Builds on the merged SHA-182 and
SHA-183 work: `noxfile.py` already defines `lint`, `typecheck` and the eleven `tests` cells,
and `nox.options.sessions` already lists all three, so AC5 is met by the current noxfile and
this ticket adds the test that pins it.

## Approach

One workflow, `.github/workflows/ci.yml`, triggered by `pull_request` targeting `main` and
`push` to `main`, with three independent jobs and no `needs` between them so a lint failure
never stops the tests (AC2). `lint` and `typecheck` run `nox -s lint` and `nox -s typecheck`
on Python 3.12. `tests` is a static GitHub matrix over `python` and `django` with one
`exclude` entry for Python 3.13 with Django 4.2, and each cell runs exactly one nox session,
`nox -s "tests(python='X', django='Y')"`, so the Actions UI shows one status per cell (AC1)
and a Django 4.2 regression fails only those three cells (AC3). Interpreters come from
`actions/setup-python`; `astral-sh/setup-uv` with caching is installed so nox's `uv|virtualenv`
backend and the `pip install -e .[dev]` steps are fast. `concurrency` cancels superseded runs
per ref. The README gets a short "CI" section naming the checks to mark as required.

Rejected: generating the matrix dynamically from `nox -l --json` in a first job (harder to
read in the UI and makes T5 meaningless; the static matrix plus T5 gives the same no-drift
guarantee); a single job running `nox` end to end (one status, AC1 and AC3 fail); running the
throwaway lint and Django 4.2 probes as commits on the real PR (leaves noise on `main` after
rebase merges; use a throwaway branch instead, see T2 and T3).

## Changes

- `.github/workflows/ci.yml`: triggers, `concurrency`, `permissions: contents: read`, jobs
  `lint`, `typecheck`, `tests` (matrix `python: [3.10, 3.11, 3.12, 3.13]` as strings,
  `django: ["4.2", "5.1", "5.2"]`, `exclude: [{python: "3.13", django: "4.2"}]`,
  `fail-fast: false`). Steps: checkout, setup-python, setup-uv with cache, `pip install nox`,
  the nox command. A pre-commit cache keyed on `.pre-commit-config.yaml` for the SHA-182 T4
  test.
- `README.md`: "CI" section listing the jobs and the note that `lint`, `typecheck` and every
  `tests (...)` cell should be required status checks on `main` (a repo setting, done by hand).
- `tests/test_ci_workflow.py`: static checks on `ci.yml` (PyYAML is already a dependency).

## Test mapping

- T1 -> the workflow runs on this ticket's PR and on `main` after merge; both run URLs are
  recorded in the PR and the Linear comment.
- T2 -> throwaway branch `ci-probe-lint` with an unused import, draft PR opened, lint job
  red and all tests jobs green; PR closed unmerged, run URL recorded.
- T3 -> throwaway branch `ci-probe-django42` with a test asserting `django.VERSION[0] >= 5`;
  only the three Django 4.2 cells red; PR closed unmerged, run URL recorded.
- T4 -> `tests/test_ci_workflow.py::test_t4_nox_default_sessions_run_everything_ci_runs`
  (imports the noxfile, asserts `nox.options.sessions == ["lint", "typecheck", "tests"]`
  and that each name matches a job in `ci.yml`).
- T5 -> `tests/test_ci_workflow.py::test_t5_ci_matrix_cells_equal_noxfile_supported`
  (expands the matrix and its `exclude`, asserts the cell set equals `noxfile.SUPPORTED`).
- Extra: `test_extra_jobs_are_independent` (no job has `needs`, guarding AC2) and
  `test_extra_triggers_cover_pull_request_and_main_push` (guarding AC1 and AC4 statically).

## Sequence

1. Write `ci.yml` and the README section; run `actionlint` if available, otherwise rely
   on the first run.
2. Add `tests/test_ci_workflow.py`; `nox` green locally.
3. Open the PR; watch all 13 jobs pass (T1 part one). Fix the workflow until green.
4. Open and close the two throwaway probe PRs (T2, T3); record URLs.
5. Merge; confirm the `push` run on `main` (T1 part two); record the URL on the ticket.

## Risks and unknowns

- Job count: 13 jobs per push. Fine for a public repo; the cancel-in-progress concurrency
  keeps queues short.
- Network-dependent tests (fresh-venv install, pre-commit hook build) run in every cell;
  a flaky PyPI moment fails a cell. Retry is a button; caching pre-commit reduces exposure.
- The workflow cannot be tested locally; the first green run is the proof, so step 3 may
  take a few pushes.
- `pip caching` in the ticket scope is met by uv's cache rather than pip's, since nox uses
  the uv backend; noted as a deviation.

## Out of scope

Branch protection and required checks themselves (repo settings; documented in the README
for the owner to click); release workflow (SHA-185); the end-to-end workflow for the
shipped action (SHA-234); coverage reporting. No follow-up tickets needed.
