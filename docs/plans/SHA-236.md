## Approach

Review every page written by earlier tickets for consistency of names and commands, then
add the three missing pieces. `docs/heuristics-and-limits.md` states plainly what each
heuristic can and cannot tell a reviewer (`dynamic`, the object-scoped flag, decorator
detection through AST, composed permissions, and what a green `check` does not prove).
`CONTRIBUTING.md` carries the dev setup and conventions and the recipe for a new fixture
project, with its shell blocks identical to those in `DEVELOPMENT.md`. `docs/index.md`
links every page. Drift is prevented by tests: CLI options in `docs/cli.md` are compared
with `--help` output through `CliRunner` (argument parsing only, no Django), a link checker
resolves every relative link, and any `--flag` in a code block is verified against the CLI.

Rejected: a hosted docs site (out of scope); duplicating `DEVELOPMENT.md` content in
`CONTRIBUTING.md` by hand without a test (the test is what keeps them equal).
