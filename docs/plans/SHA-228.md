## Approach

`diff.py` is the single comparison engine, a pure function with no CLI.
`compute(base, current) -> Diff` matches routes by `(path, view)`; a `RouteChange` carries
the old and new `Route` and a tuple of `FieldChange(field, old, new)` in lockfile field
order, where nested mappings (`django_auth`, `object_scoping`) are flattened to dotted
names such as `django_auth.permission_required` and
`object_scoping.get_queryset.overridden`. A methods change is a `FieldChange`, since
methods are not part of the match. Custom permission registry differences are reported
separately as `custom_permissions_added`, `custom_permissions_removed` and
`custom_permissions_changed` (name, docstring or `used_by` changes) and never mark a route
as changed by themselves. Every list is sorted by route key or dotted path.
`Diff.is_empty` covers all six lists.

Rejected: matching routes by path only (a view move would look like a permission change;
the key includes the view so it shows as remove plus add, which is honest); deep-diff
libraries (one function is enough and keeps output deterministic).

## Risks and unknowns

- Flattening must be stable for missing versus null nested values; treat a missing mapping
  as all-null so `None -> False` changes are reported, not crashes.
- The same `(path, view)` can appear twice in one inventory; such routes pair in route key
  order and any surplus is added or removed.
