Implementation plan

Ticket: SHA-227 Determinism guarantees for the lockfile. Written 2026-09-30. Assumes the T5
amendment proposed alongside this plan is approved (golden files compared in every matrix
cell instead of a CI artifact-comparison job, which would need a dependent job that the
SHA-184 guard forbids).

## Approach

Determinism is enforced three ways. Tests run `authzlock update` in subprocesses under
different `PYTHONHASHSEED` values, working directories and fixture locations and compare
bytes. A serializer guard in `lockfile.dump` raises `LockfileError` if any string value looks
like an absolute path (`/`, `\\` or drive-letter prefixed) so machine-specific data can never
be written. Golden files `tests/fixtures/<fixture>/authz.lock.expected` for `function_views`
and `drf_viewsets` are compared byte for byte in every nox cell, which is the cross-Python
and cross-machine check; a `--update-golden` pytest option regenerates them. Any
nondeterminism found in extraction (set iteration, `dir()` order, unsorted registries) is
fixed at the source.

Rejected: hashing the lockfile in CI and comparing across jobs (needs `needs:` between
jobs); allowing a `generated_by` header (would break byte-equality by design).

## Changes

- `src/authzlock/lockfile.py`: absolute-path guard.
- `tests/test_determinism.py`; `tests/conftest.py`: `--update-golden` option.
- `tests/fixtures/*/authz.lock.expected` for the two fixtures.
- `docs/lockfile.md`: "What is guaranteed to be stable".

## Test mapping

- T1 -> `test_t1_hash_seeds_give_identical_bytes` (seeds 0, 1, 2, 3, random).
- T2 -> `test_t2_working_directory_does_not_matter`.
- T3 -> `test_t3_fixture_location_does_not_matter` (two temp copies).
- T4 -> `test_t4_no_machine_specific_strings` (regex scan).
- T5 -> `test_t5_golden_lockfile_matches_in_every_cell` (per fixture).
- T6 -> `test_t6_serializer_rejects_absolute_paths`.

## Sequence

1. T4 and T6 with the guard.
2. T1 to T3; fix any nondeterminism found.
3. Golden files and T5; run the full matrix.

## Risks and unknowns

- Django or DRF versions could legitimately produce different routes (for example a
  format-suffix pattern); if a golden file differs by version, the fixture is simplified
  rather than the test weakened, and the difference is documented.

## Out of scope

Stability across framework versions where routes genuinely differ. No follow-up needed.
