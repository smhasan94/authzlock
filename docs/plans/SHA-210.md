Implementation plan

Ticket: SHA-210 Object-scoped heuristic for get_queryset, get_object and perform_create.
Written 2026-09-30. Builds on SHA-205 and the AST helpers from SHA-209.

## Approach

`extract/scoping.py::resolve(view_class) -> dict[str, HookInfo]` for the three hooks. A hook
is `overridden` when some class in the MRO before the first framework base
(`GenericAPIView`, `GenericViewSet`, `SingleObjectMixin`, `MultipleObjectMixin`) defines it
in its own `__dict__`; project mixins therefore count. `references_request_user` parses the
method source with `ast` and looks for an `Attribute` chain ending in `request.user` whose
root is `self` or a name `request`; helper calls are not followed. Missing source gives
`null`. Views that are not class-based, or have no such base, get `null` entries.

Rejected: executing `get_queryset` with a fake request (forbidden and unreliable);
substring search on source text (`request.user_agent` would match).
