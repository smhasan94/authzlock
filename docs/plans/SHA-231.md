Ticket: SHA-231 End-to-end success scenario: IsOwner to IsAuthenticated on DELETE. Written
2026-09-30. Builds on SHA-230 and SHA-211.

## Approach

A dedicated fixture `scenario_loosen/` has one `RetrieveDestroyAPIView` at
`invoices/<int:pk>/` with `permission_classes = [IsAuthenticated, IsOwner]` and a custom
`IsOwner` with a docstring. The test builds a temp git repo from the fixture with
`make_repo`, commits `authz.lock`, then applies the "PR" by rewriting the views module (the
string `, IsOwner` removed) and runs `authzlock diff --base HEAD --format markdown` and
`authzlock check` as subprocesses. Assertions are on exact fragments: a `loosened` row,
`DELETE`, the path, the view name and `R2`. The reverse patch proves `tightened`, and a
variant that swaps in `IsTenantAdmin` proves `changed-unknown`. `docs/scenario.md` embeds
the real markdown output between `<!-- scenario:start -->` and `<!-- scenario:end -->`
markers; a pytest option `--update-docs` rewrites that block, and without the option the
test fails with a hint if the block is stale.

Rejected: keeping the scenario inside `drf_apiview` (the fixture would need to be mutated
in place; a small dedicated fixture is clearer to read in the docs).
