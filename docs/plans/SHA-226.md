Implementation plan

Ticket: SHA-226 authzlock check command. Written 2026-09-30, revised 2026-10-01. Builds on
SHA-225 and on the diff engine from SHA-228, which now lands first.

## Approach

`check` loads the lockfile (`LockfileError` and a missing file both exit 2, the latter with
the hint to run `authzlock update`), extracts the current inventory, and compares the two
parsed `Inventory` objects with SHA-228's `diff.compute(base, current)`: `added`, `removed`
and `changed` routes, each change a tuple of `FieldChange(field, old, new)` with nested
fields dotted, plus custom permission registry changes. `check` adds no comparison logic.
`render.py::render_check(diff) -> str` prints three groups with one line per route (route
key) and `field: old -> new` lines under changed routes, a short group for registry
changes, then the hint to run `update` and commit. Exit 0 with "authz.lock: up to date"
when `Diff.is_empty`, else 1.

Rejected: comparing lockfile bytes (formatting-only edits would fail AC6); a separate
comparison in `check` instead of the shared engine.
