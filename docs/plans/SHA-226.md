## Approach

`check` loads the lockfile (`LockfileError` and a missing file both exit 2, the latter with
the hint to run `authzlock update`), extracts the current inventory, and compares the two
parsed `Inventory` objects. The comparison is the first cut of `diff.py::compute()`: routes
matched by `(path, view)`, giving `added`, `removed` and `changed` with a flat list of
`FieldChange(field, old, new)` over top-level route fields. SHA-228 extends this engine
with nested flattening and registry changes; `check` will not need to change again.
`render.py::render_check(diff) -> str` prints three groups with one line per route (route
key) and `field: old -> new` lines under changed routes, then the hint to run `update` and
commit. Exit 0 with "authz.lock: up to date" when the diff is empty, else 1.

Rejected: comparing lockfile bytes (formatting-only edits would fail AC6); a separate
comparison in `check` that SHA-228 would later have to replace.
