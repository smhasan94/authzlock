Implementation plan

Ticket: SHA-245 Later: ignore list for routes. Written 2026-09-30. Assumes the acceptance
criteria, T-cases and dependencies proposed alongside this plan are approved (the ticket is
a Later placeholder with both sections still to be written). Builds on SHA-230 and SHA-211.

## Approach

The list is given once, on `update`, and recorded in the lockfile so every later command
reads it from there. `update` gains repeatable `--ignore-path PREFIX` and
`--ignore-view PREFIX` options and `--no-ignore`; without any of them it keeps the list the
existing lockfile carries, with any of them it replaces the whole list. The lockfile gains
an optional top-level `ignore` key with `paths` and `views` lists, sorted and deduplicated,
written after `schema_version` and only when non-empty, so lockfiles written before this
ticket stay byte-identical and the schema stays at 1. `ignore.py` holds
`IgnoreList(paths, views)`, `matches(route)` and `apply(inventory, ignore) -> Inventory`.
A path prefix is compared literally to the recorded `path` after stripping one leading `^`
on each side, so `admin/` covers `re_path` routes too; a view prefix matches on a module
boundary (`view == prefix` or `view.startswith(prefix + ".")`). `apply` drops matching
routes, trims their keys from every `used_by`, and drops a custom permission whose
`used_by` becomes empty. `check` applies the lockfile's list to the fresh extraction.
`diff` applies the working-tree lockfile's list (the base lockfile's when the working tree
has none); `diff.compute` does not compare the lists, but when they differ the text and
markdown output carry one note line, and the routes the change drops or restores show as
`removed` or `added`, which is the signal a reviewer needs. Extraction and `_dump` are
unchanged; filtering happens in the CLI after `extract()`.

Rejected: filtering inside `walk_urlconf` (would hide routes from `_dump` and from the
registry before `used_by` is built); glob or regex patterns (prefixes cover admin, debug
toolbar and static mounts, and stay readable in the lockfile); a config file for the list
(SHA-238 can add a `[tool.authzlock]` key later that feeds the same options).

## Risks and unknowns

- The admin fixture needs `auth`, `contenttypes`, `sessions`, `messages`, a templates
  setting and the matching middleware for Django's system check to pass; copy the settings
  from a `startproject` template and keep the app list minimal.
- Admin route counts differ across Django versions; tests assert absence of `admin/`
  routes and equality of the remaining routes with an unfiltered run, never a count.
- A lockfile containing `ignore` is rejected by releases older than this ticket; the key
  only appears when a user opts in, so no schema bump is needed.

## Out of scope

`[tool.authzlock]` configuration (SHA-238); ignoring by HTTP method or route name; hiding
ignored routes from `_dump`. No follow-up tickets needed.
