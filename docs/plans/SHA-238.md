## Approach

`config.py` finds the nearest `pyproject.toml` at or above the current directory, parses it
with `tomllib` (`tomli` on Python 3.10) and returns a frozen `Config(settings, lockfile,
fail_on, path)` with `None` for every absent key; no file or no `[tool.authzlock]` table
gives an all-`None` config. An unknown key, a non-string value, a `fail_on` other than
`any` or `loosened`, or unparseable TOML raises `ConfigError` (new `AuthzlockError`
subclass, exit 2) naming the file and the key or line. `cli.py` changes `--settings`,
`--lockfile` and `--fail-on` to default to `None` (help text still shows `authz.lock` and
`any`) and resolves them in one helper `_effective_options(...)`: settings is flag, then
`DJANGO_SETTINGS_MODULE`, then config; lockfile and fail_on are flag, then config, then the
built-in default. A config `lockfile` is resolved relative to the directory holding
`pyproject.toml`, so `update`, `check`, the pre-commit hook and the action agree on the
file whatever the working directory. When settings came from config, the `ProjectLoadError`
text gains a line naming the config file. `_dump.py` and the harness never read config.

Rejected: a separate `authzlock.toml` (one more file to discover); ignoring unknown keys (a
misspelled `lock_file` would be a silent no-op); an `AUTHZLOCK_LOCKFILE` environment
variable (nothing asks for it); stopping discovery at the git top level (`update` and
`check` must work outside git).

## Changes

- `src/authzlock/config.py` (`Config`, `find_pyproject`, `load_config`); `errors.py`
  gains `ConfigError`; `cli.py` option defaults and `_effective_options`.
- `pyproject.toml`: dependency `tomli>=2; python_version < "3.11"`, and `tomli` in `dev`
  unconditionally so mypy (`python_version = "3.10"`) resolves the import on every runner.
- `tests/test_config.py` (unit, `tmp_path`, no Django) and `tests/test_cli_config.py`
  (subprocess through `run_cli`, fixture copied next to a generated `pyproject.toml`).
- `docs/cli.md` Configuration section with the example table and the precedence rule;
  `docs/backlog.md` row for SHA-238 gets its estimate and dependencies.

## Risks and unknowns

- Walking up to the filesystem root can pick up an unrelated `pyproject.toml` from a parent
  checkout; the first file found wins and every config message prints its path.
- Typer shows nothing for `None` defaults; the help strings carry the defaults by hand and
  the extra test pins them.

## Out of scope

Per-command tables, `--config` and `--no-config` flags, environment variables for lockfile
and fail_on, and configuration for the GitHub Action (its inputs stay explicit). No
follow-up tickets needed.
