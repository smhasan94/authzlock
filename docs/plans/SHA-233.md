## Approach

`.pre-commit-hooks.yaml` at the repo root declares `authzlock-check` (entry
`authzlock check`, `language: python`, `pass_filenames: false`, `always_run: true`) and
`authzlock-update` (entry `authzlock update`; pre-commit fails a hook that modifies files,
so a stale lockfile fails once and passes on the second run). The hook environment only
contains authzlock, so `docs/pre-commit.md` tells users to add their project's Django and
DRF through `additional_dependencies` and to supply settings via the environment or
`args: ["--settings", "proj.settings"]`. Tests drive `pre-commit try-repo <checkout>`
against a temp git repo built from the `drf_viewsets` fixture, marked `slow`.

Rejected: a shell-language hook (would need authzlock preinstalled; the python language
gives an isolated env); running `update` by default (hooks should not rewrite files
silently).
