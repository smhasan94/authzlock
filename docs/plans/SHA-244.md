## Approach

`authzlock gen-tests` reads `authz.lock` with `lockfile.load` and writes one pytest module,
default `tests/test_authz_lock.py` (`--output` to change it, `--lockfile` as on every
command). Django is never imported at generation time, so the command runs in-process
under `CliRunner`. `gen_tests.py` has three pure functions. `plan_route(route) -> RouteTest`
decides per route: `permission_classes` equal to `dynamic`, or containing anything outside
the four ranked built-ins from `classify.BUILTIN_RANK` (a custom class, a composed
expression, a third-party class), gives a skipped test whose reason names the first such
entry; `IsAuthenticated` and `IsAdminUser` assert every method in `methods`;
`IsAuthenticatedOrReadOnly` asserts only POST, PUT, PATCH and DELETE; `django_auth` with
`login_required` true or a non-empty `permission_required` asserts every method (`any`
becomes GET) and widens the accepted statuses to 302, 401 and 403 because the decorators
redirect; `user_passes_test` as the only signal gives a skipped test. A route with nothing
to assert produces no test and is counted. `build_url(path)` replaces `<int:x>` and unnamed
converters with `1`, `<slug:x>` and `<str:x>` with `x`, `<uuid:x>` with a fixed UUID,
strips `^` and `$` from regex paths and replaces groups with `1`; a remainder that still
holds regex metacharacters (format suffixes, optional parts) gives a skipped test with the
pattern in the reason. `render_module(tests) -> str` emits a header naming the lockfile and
the regenerate command, a session fixture that calls `django.setup()` and
`setup_test_environment()` only when neither has run (so pytest-django users are not
affected), one function per route named from the route key with a numeric suffix on
collision, `@pytest.mark.parametrize("method", [...])` on assertion tests and
`@pytest.mark.skip(reason=...)` on the rest. No timestamps, so output is byte-stable and the
file is written only on change, as `update` does. Summary line: "tests/test_authz_lock.py:
12 routes, 7 tests, 3 skipped, 2 without assertions". Exit 0, or 2 for lockfile errors and
unwritable paths.

Rejected: generating from live extraction (the lockfile is the reviewed artifact, and
reading it keeps the command free of Django); `reverse()` with route names (unnamed routes
and required kwargs); assertions for routes mixing a built-in with a custom class (the
ticket says custom means skipped; a follow-up can relax this); requiring pytest-django.

## Changes

- `src/authzlock/gen_tests.py`: `RouteTest`, `plan_route`, `build_url`, `render_module`.
- `src/authzlock/cli.py`: `gen-tests`.
- `tests/harness.py::run_generated_tests(fixture, tmp_path, *, patch=None)`: copy the
  fixture, write its lockfile (golden or `update`), run `gen-tests`, run pytest on the
  output in a subprocess with the fixture environment and an empty ini so the repo's own
  `conftest.py` is not collected.
- `tests/test_gen_tests.py`; `docs/cli.md` `gen-tests` section;
  `docs/heuristics-and-limits.md` paragraph on what a green generated suite does not prove.

## Risks and unknowns

- The generated tests must never touch the database, since fixture models are unmanaged:
  DRF checks permissions before `get_object`, decorators run before the view, and an
  anonymous client has no session key, so nothing loads. T9 uses a view without a queryset
  for the same reason.
- `SessionAuthentication` gives 403 and header-based classes give 401; the accepted set
  covers both, and `docs/cli.md` says a 404 means the sample URL did not match.
- Fixture settings may need `MIDDLEWARE` and `ALLOWED_HOSTS` adjustments for the test
  client; `setup_test_environment()` covers `testserver`.

## Out of scope

Authenticated-user assertions, custom permission logic, per-method permissions (SHA-239).
Follow-up if wanted: assertions for routes that pair a built-in with a custom class.
